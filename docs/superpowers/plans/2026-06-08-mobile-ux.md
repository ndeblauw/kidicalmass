# Mobile UX Refinement Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the public site work well on phones — eliminate horizontal overflow at 390px and give the shared layout layer correct mobile-first responsive behaviour.

**Architecture:** Fix the shared CSS layer first (cascades to all pages via the role-based CSS-partials architecture), then mop up page-specific issues. Mobile-first, named breakpoints (`sm 480 / md 768 / lg 1024`). No container queries, no nav redesign, no new dependencies.

**Tech Stack:** Laravel 12 Blade + Tailwind v4 + role-based CSS partials (`resources/css/`), Livewire 4, Flux UI. The automated test suite gains only a fast pure-PHP Pest render test. Overflow is verified by an **on-demand Node/Playwright script that is NOT part of `php artisan test`** (Playwright is installed globally; it needs a running browser + the Herd server, so it stays a manual dev/pre-merge tool, like the existing `scripts/mobile-audit.cjs`).

**Spec:** `docs/superpowers/specs/2026-06-08-mobile-ux-design.md`

**Conventions (from CLAUDE.md — do not violate):**
- New CSS goes in role-based partials under `resources/css/` (components/ or pages/), never piled into `app.css`. `app.css` holds only `@theme`, `@layer base`, `@import`.
- No raw hex/px in `.blade.php` components — use tokens (`var(--color-kidical-*)`, `--text-*`, `--spacing`). Page templates may use layout utilities (`grid`, `flex`, `gap-*`, `p-*`, `max-w-*`).
- Headings: raw `<h1>`–`<h6>`, never `flux:heading`.
- No em-dashes in any copy. Follow `docs/tone-of-voice.md`.
- Run `vendor/bin/pint --dirty --format agent` before each commit that touches PHP.
- Keep `php artisan test --filter=CssArchitectureTest` green.
- Shared working tree: stage specific files, never `git add -A`; do not push `main`.

**Note on testing approach (refined from spec):** the spec floated a "Pest browser test", but the project has NO Pest browser plugin installed and adding one is a dependency change requiring approval — and a browser-driven test would be too slow/heavy to belong in `php artisan test` anyway. So:
- **In the suite (fast):** a pure-PHP Pest feature test asserting key routes return 200 (`PublicPagesRenderTest`). This is what runs in `php artisan test` and satisfies the "every change is programmatically tested" rule by guarding against render regressions.
- **Manual / pre-merge (on demand):** the Node/Playwright overflow-check script, run by hand during development and once before merge. It is NOT invoked by `php artisan test`. During iteration, pass it the single route you are editing so it loads one page, not all 19.

## Task 1: Overflow verification tool + render smoke test (do first)

This task creates two things with different roles: a **manual** overflow-check script (run on demand, never in the suite) and a **fast in-suite** render test.

**Files:**
- Create: `scripts/mobile-overflow-check.cjs`
- Create: `tests/Feature/PublicPagesRenderTest.php`

- [ ] **Step 1: Write the overflow-check script (manual tool, accepts route args)**

It checks all 19 routes by default, but accepts route args so during iteration you load only the page you are editing (one browser context, ~2s) instead of all 19:

```js
// scripts/mobile-overflow-check.cjs
// MANUAL dev tool — NOT part of `php artisan test`. Exit 1 if any route overflows at 390px.
//   node scripts/mobile-overflow-check.cjs                  # full 19-route sweep (pre-merge)
//   node scripts/mobile-overflow-check.cjs /nl/events       # just one route (fast, during iteration)
const path = require('path');
const { execSync } = require('child_process');
const globalRoot = execSync('npm root -g').toString().trim();
const { chromium } = require(path.join(globalRoot, 'playwright'));

const BASE = process.env.APP_URL || 'https://kidicalmass.test';
const VP = { width: 390, height: 844 };
const ALL = [
    '/nl', '/nl/events', '/nl/events/26', '/nl/chapters', '/nl/chapters/1',
    '/nl/getting-started', '/nl/steun-ons', '/nl/help-out', '/nl/find-a-bike',
    '/nl/about', '/nl/about/mission', '/nl/about/vision', '/nl/about/organisation',
    '/nl/about/partners', '/nl/about/press', '/nl/about/news', '/nl/about/news/1',
    '/nl/contact', '/nl/privacy',
];
const ROUTES = process.argv.slice(2).length ? process.argv.slice(2) : ALL;

(async () => {
    const browser = await chromium.launch();
    const offenders = [];
    for (const route of ROUTES) {
        const ctx = await browser.newContext({ ignoreHTTPSErrors: true, viewport: VP, deviceScaleFactor: 2, isMobile: true, hasTouch: true });
        const page = await ctx.newPage();
        await page.goto(BASE + route, { waitUntil: 'networkidle', timeout: 30000 });
        const { scrollW, clientW } = await page.evaluate(() => ({
            scrollW: document.documentElement.scrollWidth,
            clientW: document.documentElement.clientWidth,
        }));
        const overflow = scrollW - clientW;
        if (overflow > 1) offenders.push({ route, overflow });
        console.log(`${overflow > 1 ? 'FAIL' : 'ok  '} ${route.padEnd(28)} overflow=${overflow}px`);
        await ctx.close();
    }
    await browser.close();
    if (offenders.length) {
        console.error(`\n${offenders.length} route(s) overflow at 390px.`);
        process.exit(1);
    }
    console.log('\nAll checked routes fit at 390px.');
})();
```

## Task 3: Kalender mobile layout (M1, M3)

`calendar.css` currently has zero `@media`. `.kal-body` is `1fr 300px`, `.kal-sidebar` is a fixed 300px column, `.kal-filterrow` is a non-wrapping flex row with `padding/margin 2rem`. On mobile this forces ~+254px overflow.

**Files:**
- Modify: `resources/css/pages/calendar.css` (append a mobile block inside the existing `@layer components`)

- [ ] **Step 1: Add the mobile layer**

Append this block at the end of `calendar.css`, INSIDE the existing `@layer components { … }` (place it before the closing brace, or wrap in its own `@layer components` block — both are valid):

```css
@layer components {
    @media (max-width: 767px) {
        /* Single column: agenda stacks, sidebar drops below it. */
        .kal-body {
            grid-template-columns: 1fr;
            gap: 2rem;
            margin-top: 1.5rem;
        }
        .kal-sidebar {
            position: static;
            top: auto;
        }
        /* Filter row wraps; trim the negative margin/padding so it never pushes width. */
        .kal-filterrow {
            flex-wrap: wrap;
            gap: 0.75rem 1rem;
            padding: 0.75rem 1rem;
            margin: 0 -1rem;
        }
        .kal-filterrow__sep {
            display: none;
        }
        .kal-filterrow__radius {
            flex-wrap: wrap;
        }
        .kal-filterrow__tabs {
            flex-wrap: wrap;
        }
        /* Day grid: narrower date column so the rides column has room. */
        .kal-day {
            grid-template-columns: 56px 1fr;
            gap: 0 0.85rem;
        }
    }
}
```
